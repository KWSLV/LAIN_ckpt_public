## 修改目的

原 `SceneGate V5` 虽接收 `scene_gate_rank`，但实际门控预测器是
`1024 -> hidden_dim -> 1`，`rank` 不参与结构。新增 `v5_lowrank`，让
`scene_gate_rank` 真正控制瓶颈宽度，同时不改变 V5 的其余算法逻辑。

## 代码修改

1. `models/scene_gate_v5.py`
   - 新增 `SceneGatePairV5LowRank`。
   - 门控预测器由父类构造成 `2*dim -> rank -> 1`。
   - 保留 V5 的输入 LayerNorm、detach、`standardized_tanh`、pair-relative
     零均值调制、`alpha`、zero/shuffle/random 消融和 diagnostics。
   - 新增 `build_scene_gate_v5_lowrank`。
2. `models/LAIN.py`
   - 支持 `scene_gate_version=v5_lowrank`，并把 `scene_gate_rank` 传入真实低秩构造器。
3. `main.py`、`utils/args.py`
   - 将 `v5_lowrank` 加入合法版本并保持 pair gate 约束。
4. 训练脚本
   - 新增 `scripts/training/UO_a4all_v5lowrank.sh`。
   - 新增 `scripts/training/UO_a4all_v5lowrank_background.sh`。
   - 扩展公共脚本 `UO_a3all_a4all_common.sh`，支持独立的
     `a4all_v5lowrank` 运行与参数一致性校验。


## 输出位置

```text

```

最初计划输出到 `/root/autodl-tmp/Lain/UO_a4all_v5lowrank_seed66`，但启动前磁盘保护检查发现
该 50 GiB 数据盘只剩约 3.5 GiB，而 20 个 checkpoint 预计需要约 13.7 GiB（另需安全余量）。
当时训练没有开始。用户随后清理出约 14.8 GiB 可用空间。公共挂载 `/autodl-pub/data`
实际上是只读公共数据集，不能作为训练输出。本次根据现有 A4ALL checkpoint 的实测平均大小
703 MiB，将 lowrank 运行的磁盘预算校准为 704 MiB/轮，并保留 512 MiB 安全余量；训练输出仍放在
用户数据盘，不删除任何剩余历史 checkpoint。两次失败尝试都在模型训练前退出，仅追加了小型日志。

后台会话默认名称：

```text

```

## 对照解释边界

本次没有开启 post-gate L2，也没有降低 Gate 学习率，因为目标是只比较
“H128 普通 MLP”与“rank-16 低秩预测器”。若同时修改归一化或学习率，结果将无法归因于低秩化。
