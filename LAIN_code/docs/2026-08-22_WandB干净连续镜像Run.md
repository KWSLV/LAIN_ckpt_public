- 原 W&B Run：`j7q84llg`
- 训练恢复点：`ckpt_23370_05.pt`

## 原因

原 W&B Run 经历多次 resume。指标 history 能正常续写，但控制台日志的
`console_offset` 在恢复时重新从 0 计数，导致新日志覆盖旧偏移区域，网页 Logs
尾部看起来没有更新。

## 修改

新增 `scripts/wandb_mirror_dynamic_retry.py`。该程序不修改、不暂停训练进程，
创建一个全新的 W&B Run，并完成以下工作：

1. 从 `scene_gate_diagnostics.json` 回填 Epoch 1～5 已接受结果。
2. rollback 后被拒绝的尝试不写入正常曲线。
3. 从本次 Epoch 5 恢复标记开始，实时同步训练控制台日志。
4. 解析训练心跳并同步当前 logical epoch、iteration 及三个学习率。
5. 后续每个 accepted epoch 自动写入 Full/Unseen/Seen mAP、模块消融、模块贡献、
   Object/Head/ViT LR、下一轮 LR、retry 和 rollback 信息。
6. 达到 Epoch 20 后正常结束镜像 Run。

镜像进程采用独立 session 后台运行，不依赖 SSH 会话，不会影响当前 GPU 训练。
